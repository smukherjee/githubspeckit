## Schema Fixes Applied

### 1. Roles Table - PK Naming Exception
- **Column**: `id` (NOT `role_id`)
- **Rationale**: Tests expect `role["id"]` in JSON responses, 20+ files reference this pattern
- **Decision**: KEEP as exception (well-documented in PK_NAMING_ANALYSIS.md)

### 2. User Roles Table - Critical Fixes
**OLD (broken)**:
```sql
role_id VARCHAR(50)  -- Wrong type, no FK constraint
-- Missing audit fields
```

**NEW (V1.0)**:
```sql
role_id UUID NOT NULL
assigned_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT now()
assigned_by UUID
FOREIGN KEY (role_id) REFERENCES roles(id) ON DELETE CASCADE
FOREIGN KEY (assigned_by) REFERENCES users(user_id) ON DELETE SET NULL
```

### 3. User Details Table - Constraint Naming Standardization
**OLD**:
- PK: `pk_user_details` (non-standard prefix)
- FK: `fk_user_details_user_id`, `fk_created_by`, `fk_updated_by`
- Audit fields: `created_by`/`updated_by` NOT NULL (incorrect)

**NEW**:
- PK: `user_details_pkey` (standard PostgreSQL pattern)
- FK: `user_details_user_id_fkey`, `user_details_created_by_fkey`, `user_details_updated_by_fkey`
- Audit fields: `created_by`/`updated_by` NULLABLE (matches models.py, correct for non-audit table)

### 4. Tenant Status Enum
**OLD**: `('active', 'soft_deleted')`  
**NEW**: `('active', 'soft_deleted', 'disabled')` - V1.0 requirement

### 5. System Roles Seeding
```sql
-- Fixed UUIDs for test consistency
superadmin:   00000000-0000-0000-0000-000000000001
tenant_admin: 00000000-0000-0000-0000-000000000002  
user:         00000000-0000-0000-0000-000000000003
```
