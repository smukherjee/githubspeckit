## Issue 1: TS-002 - Deprecated Routes Still Registered

### Problem

The quickstart validation script expected deprecated routes `/api/v1/tenants` and `/api/v1/users` to return 404 (Not Found), but they were returning 401 (Unauthorized). This indicated the routes were still registered in the FastAPI application.

### Root Cause

In `src/adapters/api/app.py` lines 331 and 337, the deprecated router registrations were still active:

```python
app.include_router(users_router.router, prefix="/api")  # Creates /api/v1/users
app.include_router(tenants_crud.router, prefix="/api")  # Creates /api/v1/tenants
```

According to FR-115 in the V1.0 specification, these routes should have been migrated to:
- `/api/v1/tenants` → `/api/v1/admin/tenants`
- `/api/v1/users` → `/api/v1/admin/users`

### Solution

**1. Removed Deprecated Route Registrations** (`src/adapters/api/app.py`):

```python
# V1.0: Include routers - Unified /api/v1/admin/* prefix for admin routes
app.include_router(invitations_router.router, prefix="/api")  # Deferred to Phase 2 (spec 015)
# app.include_router(users_router.router, prefix="/api")  # V1.0 REMOVED: Migrated to /api/v1/admin/users (FR-115)
# app.include_router(tenants_crud.router, prefix="/api")  # V1.0 REMOVED: Migrated to /api/v1/admin/tenants (FR-115)
app.include_router(auth_router.router, prefix="/api")  # Public auth endpoints
```

**2. Updated Validation Approach** (`scripts/validate_v1_quickstart.sh`):

Changed from testing HTTP status codes (which can't distinguish between "route doesn't exist" vs "route exists but auth failed") to checking the OpenAPI schema:

```bash
# TS-002: Deprecated Routes Removed from OpenAPI Schema
# NOTE: TenantContextMiddleware runs BEFORE route matching and returns 401 for any 
# non-public route without authentication. This is MORE SECURE than returning 404.
# Verification: Check OpenAPI schema to confirm routes are not registered.

OPENAPI_PATHS=$(curl -s "${BASE_URL}/openapi.json" | jq -r '.paths | keys[]' | grep -E '/(tenants|users)' | sort)

# Check that deprecated routes are NOT in OpenAPI schema
if echo "$OPENAPI_PATHS" | grep -q "^/api/v1/tenants$" || echo "$OPENAPI_PATHS" | grep -q "^/api/v1/users$"; then
    print_result "FAIL" "Deprecated routes still registered in OpenAPI schema"
else
    print_result "PASS" "Deprecated routes successfully removed (not in OpenAPI schema)"
fi
```

**3. Updated Documentation** (`specs/012-v1-cleanup-legacy-removal/quickstart.md` TS-002):


## Issue 2: TS-004 - Login Endpoint Returns FileNotFoundError

### Problem

The login test was failing with a `FileNotFoundError: Config descriptor not found: config/descriptor.toml` error.

### Root Causes

**1. Wrong Login Endpoint Path**: The validation script was calling `/api/v1/auth/token` but the actual endpoint is `/api/v1/auth/login`:

```bash
# ❌ WRONG
curl -X POST "${BASE_URL}/api/v1/auth/token" \
    -H "Content-Type: application/x-www-form-urlencoded" \
    -d "username=...&password=..."

# ✅ CORRECT
curl -X POST "${BASE_URL}/api/v1/auth/login" \
    -H "Content-Type: application/json" \
    -d '{"email":"...","password":"..."}'
```

**2. Server Started from Wrong Directory**: The server was being started from `src/adapters/api` directory, causing the relative path `config/descriptor.toml` to fail:

```bash
# ❌ WRONG (from src/adapters/api)
cd src/adapters/api && uvicorn app:app --reload
# Looks for: src/adapters/api/config/descriptor.toml (doesn't exist)

# ✅ CORRECT (from project root)
python -m uvicorn src.adapters.api.app:app --factory --reload
# Looks for: config/descriptor.toml (exists)
```

### Solution

**1. Fixed Login Endpoint in Validation Script** (`scripts/validate_v1_quickstart.sh`):

```bash
# TS-004: Successful Admin Login Returns JWT
LOGIN_RESPONSE=$(curl -s -X POST "${BASE_URL}/api/v1/auth/login" \
    -H "Content-Type: application/json" \
    -d '{"email":"infysightsa@infysight.com","password":"infysightsa123"}')
```

**2. Server Must Be Started from Project Root**:

The correct way to start the server is using the Makefile from the project root:

```bash
make server-start
# OR manually:
export DATABASE_URL="postgresql://..."
python -m uvicorn src.adapters.api.app:app --factory --host 0.0.0.0 --port 8000 --reload
```

The Makefile target (lines 102-107) ensures:
- Server runs from project root
- Environment variables are set (`DATABASE_URL`, etc.)
- Server starts in background with logging to `/tmp/githubspeckit-api.log`
- PID is tracked in `/tmp/githubspeckit-api.pid`

## Security Note: 401 vs 404 Behavior

**Design Decision**: The deprecated routes return 401 (Unauthorized) instead of 404 (Not Found) due to `TenantContextMiddleware` running **before** FastAPI route matching.

**Why This Is More Secure**:
- ❌ 404 response: Leaks information about which endpoints exist ("route not found")
- ✅ 401 response: Does not leak endpoint existence ("you need to authenticate first")

This follows the principle of **security through obscurity** at the HTTP layer. Unauthenticated users cannot determine which routes are valid without first authenticating.

**Verification Method**: Check the OpenAPI schema (which requires authentication to access sensitive routes) to confirm route presence, not HTTP status codes.

## Lessons Learned

1. **Route Verification**: HTTP status codes alone cannot determine if a route is registered when middleware intercepts requests before routing. Use OpenAPI schema inspection instead.

2. **Server Startup Location**: FastAPI apps using relative paths for config files must be started from the project root. Use Makefile targets to enforce correct startup procedures.

3. **Endpoint Naming**: Always verify actual endpoint paths against OpenAPI spec. Assumptions about endpoint names (e.g., `/token` vs `/login`) can cause integration failures.

4. **Security First**: Returning 401 for all unauthenticated requests (even to non-existent routes) is more secure than 404, as it doesn't leak endpoint existence information.
