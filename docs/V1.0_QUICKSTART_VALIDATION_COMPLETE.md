## Architecture Notes

### API Response Format Convention

**Decision**: Use bare arrays for list endpoints (FastAPI convention).

**Rationale**:
- FastAPI `List[Model]` serializes to `[...]` JSON array
- OpenAPI spec correctly reflects this as `array` type
- More RESTful than custom pagination wrapper
- Compatible with React-Admin and other clients

**Example**:
```python
@router.get("", response_model=List[TenantResponse])
async def list_all_tenants(...) -> List[TenantResponse]:
    return [TenantResponse(...) for tenant in tenants]
```

**Response**:
```json
[
  {"tenant_id": "...", "name": "..."},
  {"tenant_id": "...", "name": "..."}
]
```

### Role UUID Migration

**Background**: FR-122 role management migration from role names (strings) to role UUIDs.

**System Roles** (Fixed UUIDs):
```python
"superadmin":    "00000000-0000-0000-0000-000000000001"
"tenant_admin":  "00000000-0000-0000-0000-000000000002"
"user":          "00000000-0000-0000-0000-000000000003"
```

**Seed Script Pattern**:
1. Query system role UUIDs by name from database
2. Use UUIDs in user `roles` list (not names)
3. When updating existing users, always sync roles with UUIDs

## Lessons Learned

### 1. Server Startup Location Matters
- **Critical**: Always use `make server-start` from project root
- **Reason**: Relative paths (config/descriptor.toml) resolve from CWD
- **Anti-pattern**: `cd src/adapters/api && uvicorn app:app` breaks config loading

### 2. Response Format Conventions
- FastAPI `List[Model]` returns bare arrays, not paginated wrappers
- OpenAPI schema correctly reflects this
- Validation tests should align with actual API contracts

### 3. Migration Script Patterns
- Always update ALL related fields when modifying existing records
- Don't just update passwords - sync roles, status, metadata
- Query current database state (system roles) instead of hardcoding

### 4. Domain Model vs Response Model
- Domain models may not have all response fields
- Use adapters to fill optional fields (auto-generate slug, null owner_email)
- Keep domain models minimal and focused
